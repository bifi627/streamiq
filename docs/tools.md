# Tools & credentials inventory

The external tools and services StreamIQ depends on (not code libraries), why each
one exists, and every credential they need. Use this for key-rotation drills.
Version pins live in `docker-compose.yml`; bump them with the `deps-bump` skill.

## Credentials

Dev credentials are fixed, throwaway values with no rotation needed. Every prod
credential is set by a human at deploy time. None are in the repo.

Where to request or rotate credentials by hand:

- **Firebase service account key:** [Firebase console → Project settings → Service accounts](https://console.firebase.google.com/project/_/settings/serviceaccounts/adminsdk) (generate), [GCP → IAM → Service accounts](https://console.cloud.google.com/iam-admin/serviceaccounts) (list/delete keys)
- **Firebase web API key restrictions:** [GCP → APIs & Services → Credentials](https://console.cloud.google.com/apis/credentials)
- **Cloudflare TURN key + API token:** [Cloudflare dashboard](https://dash.cloudflare.com/) → Realtime → TURN Server ([docs](https://developers.cloudflare.com/realtime/turn/))
- **Railway env vars + Postgres:** [Railway dashboard](https://railway.com/dashboard) → project → service → Variables

## Rotation drill checklist

1. Pick the credential from the table and create the new one **before** revoking the old one.
2. Update it in Railway (or Cloudflare) and redeploy.
3. Exercise the flow it protects: sign-in for Firebase, `/api/me` for the DB, a forced-relay session for TURN.
4. Revoke the old credential and confirm the flow still works.
5. Write down the date here or in the PR.

## Preview env

`npm run preview --prefix e2e` (`-- status`, `-- down`; `--port N`): the e2e stack (`startStack`), detached, seeded (account `preview@streamiq.test` / `preview-password`, a gateway online, the 30 s e2e clip and a small series (`scripts/gen-test-series.sh`, a Shows library), plus the checkout's `dev-media/`, made empty if missing: `scripts/gen-test-media.sh` or your own files; files added while running need "Scan All Libraries" on the printed `jellyfin:` address, as `streamiq` / `streamiq-e2e`). Served on all interfaces over HTTPS on a port stable per worktree (41000–41999, from the worktree path), API + broker WS + auth emulator proxied to that one origin. Self-signed cert from `openssl` (ships with Git for Windows), made once per worktree in `e2e/.preview/` (gitignored), redone only when the LAN addresses change: accept it once per device. Pairing is **auto-approved** (#155): the preview approves every pending request on the local gateway page itself (the full pairing flow runs; only the code comparison is skipped), so devices pair without anyone at this machine; with `--tunnel` that includes anyone with the URL (owner accepted).

**GPU:** with an NVIDIA GPU (`nvidia-smi` works on the host), Jellyfin gets it (`--gpus all`) and NVENC is turned on; `up`/`status` print `transcoding:`. Else CPU. WebRTC goes direct to the host's LAN candidates; the e2e coturn only serves this machine.

**Windows Firewall, one time (admin PowerShell):** `New-NetFirewallRule -DisplayName 'StreamIQ preview' -Direction Inbound -Protocol TCP -LocalPort 41000-41999 -Action Allow -Profile Private` (allow `streamiq-e2e-gateway.exe` too if Windows asks). `up`/`status` also print the `api:` + auth emulator URLs, for extra seeding on top (`/preview <instructions>`: through the API as real users, never the DB; see the preview skill). Agents: start it with `up`, never as a background shell; `scripts/prune-worktrees.ps1` runs `down`.

**`--tunnel` (TV, #141):** webOS keeps the self-signed exception for navigation only, so every fetch/XHR fails there; `up --tunnel` adds a Cloudflare quick tunnel (`https://….trycloudflare.com`, trusted cert) to the same origin. On the TV bookmark `https://<LAN>:<port>/tv` once: it redirects to the current tunnel URL. Media stays direct on the LAN; signaling/API/auth go via Cloudflare.

**Public while it runs** (anyone with the URL can sign up on the emulator; test data only): `down` closes it. Already running without it? `down` first.

## Releasing the gateway

Automatic (#274): after CI passed on a push to `main` (the last job of `ci.yml`), the
gateway releases if something it builds with changed since the last stable release
(`*_test.go` aside): `gateway/`, a repo package it imports from outside `gateway/`
(`protocol/`), or in the shared `go.mod` / `go.sum` a module it builds with (per `go list`,
for each release OS) or the `go` / `toolchain` line. A dependency only the Go API uses cuts
no release (#750).
It releases what `main` is, so a change whose own push didn't release (red CI, a cancelled
run, `[skip release]` in the subject) goes out with the next one. Version
(`scripts/next-gateway-version.sh`): the highest stable `gateway-v*` tag, minor bumped if any
gateway commit since it is marked breaking with `!` right after the type (`feat!: …`,
`fix(gateway)!: …`, `feat!: gateway: …`; not `feat: gateway!: …`), else patch bumped. The
subject is the PR title (repo setting: squash commit = PR title). A re-run or an older commit never releases over a newer one.

The major never changes automatically: to bump it, push a tag `gateway-vN.0.0` by hand on a
commit on `main`; that releases it, and later automatic releases build on it.

Either way CI (`release-gateway.yml`) tests, builds all six
binaries, and publishes the GitHub Release with `SHA256SUMS`, both install
scripts and `jellyfin-compose.yml`. When bumping the Jellyfin pin, update
`docker-compose.yml`, `gateway/install/jellyfin-compose.yml`,
`jellyfin.Image` and `jellyfin.Tested` together (a gateway test enforces it). A tag with a suffix (`gateway-v1.5.0-rc.1`) becomes a prerelease,
which `latest` and the update check skip.
